# 运动异常守护设计规格

日期：2026-06-02

## 1. 产品定位

“运动异常守护”是一款面向 Zepp OS 手表的运动安全辅助应用。它在用户跑步或健走期间，根据后台可用的低功耗信号识别“持续活动后出现异常停止且用户未响应”的情况，并尽快提醒用户、引起附近人员注意、协助联系紧急联系人。

首版不宣称能够检测、预测或预防心脏骤停，也不宣称具备跌倒检测能力。腕式光学心率、设备连接、定位和消息投递均存在失败可能。应用不能替代专业医疗设备、急救服务或专业医疗建议。

建议面向用户使用以下描述：

> 本应用提供运动期间的异常提醒和求助辅助。当检测到持续活动后出现异常停止或心率异常，且用户未响应提醒时，应用可发出本地警报，并在手机连接可用时协助通知紧急联系人。传感器读数、定位和消息投递可能受设备、环境和连接状态影响。

## 2. 首版范围

首版采用通用后台守护核心方案，面向 `API_LEVEL 3.0+` 设备。

包含：

- 一次开启后常驻的手表端 `App Service`
- 低功耗持续活动推断
- 心率异常、活动停止、佩戴状态和用户响应的组合判断
- 系统通知、强震动和本地警报
- `30 秒` 未响应升级
- 应用首页主动求助入口
- 负一屏 `Secondary Widget` 快捷入口
- Zepp App 内的 `Settings App` 和 `Side Service`
- 最多 `3` 位紧急联系人
- 手机在线时的后端演示接口
- 手机离线时的本地警报和恢复连接后补发
- 用户主动打开求助页时临时获取 GPS
- 首次使用引导和无真实通知的模拟演练

首版不包含：

- 心脏骤停、猝死或疾病诊断
- 后台跌倒检测
- 后台持续 GPS
- 自动拨打当地急救电话
- 独立手机 App
- 实时短信和语音供应商接入
- `API_LEVEL 3.6+` 运动扩展

后续可单独发布 `API_LEVEL 3.6+` 的运动扩展包。该包使用独立 `appId`，作为支持设备上的系统运动页快捷入口，不替代后台守护服务。

## 3. 平台边界

### 3.1 可用于首版的公开能力

| 能力 | 用途 |
| --- | --- |
| `App Service` | 无界面后台守护，维护状态机并处理系统事件 |
| `HeartRate` | 获取后台可用的心率数值和更新时间 |
| `Step` | 获取步数变化，作为持续活动证据 |
| `Distance` | 获取距离变化，辅助识别跑步、健走和实验性骑行 |
| `Wear` | 判断佩戴状态和设备提供的活动状态 |
| `Time.onPerMinute()` | 低功耗分钟级巡检 |
| `Alarm` | 在后台不能使用 `setTimeout` 时，按秒延迟唤醒服务完成升级 |
| `notify()` | 从后台发出系统通知，并提供操作按钮 |
| `Vibrator` | 发出轻提醒和强提醒 |
| `SystemSounds` | 在支持的 `API_LEVEL 3.6+` 设备上播放系统 SOS 声音 |
| `Geolocation` | 用户主动打开前台求助页时临时获取坐标 |
| `Secondary Widget` | 从负一屏进入主动求助 |
| `Side Service` | 手表经蓝牙向手机 Zepp App 传递事件，手机侧请求后端 |

### 3.2 公开接口无法提供的能力

- 普通第三方应用无法读取“用户已在系统运动 App 中点击开始运动”的通用事件。
- 后台 `App Service` 不能使用加速度计、陀螺仪或定位等高功耗传感器。
- 后台不能强制打开自定义全屏页面。
- 公开 API 不支持第三方应用传入号码并自动拨打急救电话。
- 手机不在附近且手表没有独立通信能力时，应用无法通知联系人。
- 首版无法获得原始 PPG、心率信号质量、呼吸或脉搏确认信号。

## 4. 架构

| 模块 | 职责 |
| --- | --- |
| 手表端 `Device App` | 展示守护状态、首次引导、主动求助、事件历史和本地设置 |
| 手表端 `App Service` | 后台读取低功耗信号，维护检测状态机，调度通知、Alarm、本地警报和离线队列 |
| 手表端 `Secondary Widget` | 显示守护与连接状态，提供“我感觉不适”快捷入口 |
| 手机侧 `Settings App` | 配置年龄建议阈值、最多 `3` 位联系人、离线警报开关和隐私授权 |
| 手机侧 `Side Service` | 接收手表事件，调用可替换的联系人通知后端 |
| 演示后端适配器 | 返回模拟短信和语音投递结果；后续替换为真实供应商 |

## 5. 危险检测原则

### 5.1 产品原则

应用只判断“可能需要帮助”，不判断心脏骤停。

自动联系联系人必须满足多信号组合条件或长时间未响应条件。单个异常读数不得直接触发联系人求助。

### 5.2 输入信号

后台状态机保存以下滚动状态：

- 最近一次步数变化时间
- 最近一次距离变化时间
- 最近一次有效心率数值和更新时间
- 最近一段时间内的心率趋势
- 当前佩戴状态
- 当前活动证据
- 当前手机连接状态
- 用户是否已确认休息、取消求助或主动求助

### 5.3 持续活动推断

首版不能精确读取系统运动状态，使用“持续活动”作为实现概念：

```text
最近 2 分钟内持续存在步数变化或距离变化
且设备保持佩戴
→ 推断进入持续活动
```

`Wear` 提供的活动状态作为加权证据，不作为唯一证据。

适用性：

- 跑步、健走：核心支持
- 日常连续步行：可能进入守护，但不会立即打扰用户
- 骑行：实验性支持，主要依赖距离和心率变化
- 驾车：通过缺少活动证据和心率趋势过滤

### 5.4 心率阈值

不使用统一的 `180 bpm` 自动求助阈值。

首次设置时，根据年龄生成建议提醒值，允许用户修改。应用同时维护两个不同用途的阈值：

| 阈值 | 用途 |
| --- | --- |
| 强度提醒阈值 | 用户仍在移动时，提示降低强度 |
| 高危候选阈值 | 仅与突然停止、仍佩戴和未响应组合使用 |

高危候选阈值不得在没有真机试跑和专业顾问复核前写死为面向所有用户的产品默认值。开发阶段使用明确标记为“测试配置”的可调整值。

### 5.5 禁止单独触发联系人求助的条件

以下条件单独出现时，只能记录或提醒，不得自动联系联系人：

- 单次心率高值
- 用户仍在持续移动时的高心率
- 没有新心率读数
- 距离短时间没有变化
- 检测到设备未佩戴
- 手机蓝牙断开

## 6. 状态机

### 6.1 主状态

```text
STANDBY
→ 连续活动达到 2 分钟
→ ACTIVE_GUARD
→ 连续静止且心率恢复正常达到 10 分钟
→ STANDBY
```

检测到未佩戴后进入 `NOT_WORN`。重新佩戴并恢复活动证据后返回待机或自动守护。

### 6.2 风险等级

| 等级 | 条件 | 行为 |
| --- | --- | --- |
| 强度提醒 | 用户仍在活动，心率持续超过用户设置的强度提醒阈值 | 轻震动，建议减速，不联系联系人 |
| 普通停留 | 自动守护中静止 `3 分钟`，心率没有高危组合 | 轻震动并询问“正在休息吗？” |
| 高危候选 | 持续活动后突然停止，仍佩戴，同时持续心率异常 | 立即加急震动和系统通知，启动 `30 秒` Alarm |
| 中等风险 | 持续活动后突然停止，仍佩戴，但只有单一可疑信号 | 立即询问；累计 `60 秒` 未响应后进入联系人求助 |
| 长时间未响应 | 普通停留提醒后累计 `10 分钟` 未响应 | 进入联系人求助 |
| 主动求助 | 用户点击“我感觉不适” | 进入 `30 秒` 倒计时，可立即发送 |

“持续心率异常”的窗口与阈值属于校准项，但首版实现必须要求多个连续样本或跨越时间窗口，不能用单次读数。

### 6.3 未佩戴

```text
检测到未佩戴
→ 暂停异常判断
→ 连续 5 分钟未佩戴
→ 提醒“守护已暂停”
```

未佩戴本身不触发联系人求助。

## 7. 求助流程

### 7.1 自动高危候选

```text
检测到高危候选
→ 加急震动
→ 系统通知：“检测到运动异常，你还好吗？”
→ 创建 30 秒 Alarm
→ 用户点击“我没事”：再次确认后取消
→ 用户点击“立即联系家人”：立即发送联系人求助
→ Alarm 到时仍未响应：发送联系人求助
```

后台通知按钮只依赖点击，不依赖长按事件。前台页面可以使用长按取消交互，但后台取消采用两步确认。

### 7.2 主动求助

用户可以从应用首页或负一屏快捷卡片点击“我感觉不适”：

```text
打开前台求助页
→ 进入 30 秒倒计时
→ 并行临时启动 GPS
→ 用户可长按 2 秒取消
→ 用户可点击“立即联系家人”
→ 用户可点击“打开电话呼叫急救”
```

GPS 不阻塞求助。先发送事件；如果稍后获得坐标，再发送位置更新。结束求助后立即关闭 GPS。

### 7.3 联系人通知

手机在线时：

```text
手表发送求助事件给 Side Service
→ Side Service 请求后端
→ 同时向最多 3 位联系人发送短信
→ 按顺序拨打语音电话
```

联系人短信建议使用以下语义：

> 检测到运动异常，用户在提醒后未响应。请立即尝试联系用户。如用户失去响应或呼吸异常，请拨打当地急救电话，并尽快寻找 AED。

消息包含：

- 用户昵称
- 触发时间
- 事件类型
- 在线实时发送或离线补发状态
- 最近可用位置；没有坐标时明确标注暂未获取
- 风险解除状态

### 7.4 本地警报

手机离线或后端请求失败时：

- 持续强震动
- 支持设备播放系统 SOS 声音
- 不支持系统 SOS 声音的设备降级为应用内置警报音；该降级路径必须真机验证
- 保存待发送事件
- 恢复连接后补发联系人求助，并注明事件发生于离线期间

### 7.5 风险解除

联系人求助发送后，用户确认安全时自动发送“风险已解除”短信。

## 8. 首次使用引导

首次进入应用时必须完成完整演练，避免用户在紧急时不知道如何操作。

| 步骤 | 内容 |
| --- | --- |
| 1 | 说明应用是运动异常求助辅助，不是医疗设备 |
| 2 | 授权心率、步数、距离、佩戴状态和本地存储 |
| 3 | 说明 GPS 仅在用户主动打开求助页时临时使用 |
| 4 | 根据年龄生成心率建议值，允许调整 |
| 5 | 在手机 Zepp App 设置页中配置最多 `3` 位联系人 |
| 6 | 说明在线可通知联系人，离线只能本地警报并等待补发 |
| 7 | 展示首页和负一屏快捷卡片的主动求助入口 |
| 8 | 进行一次不会联系家人的模拟演练 |
| 9 | 练习取消、立即联系家人和打开电话入口 |
| 10 | 用户确认理解能力边界后开启自动守护 |

未配置联系人时仍允许使用本地守护，但首页持续提示完善联系人配置。

## 9. 日常界面

首页保持极简：

```text
自动守护：已开启
远程求助：手机在线 / 离线仅本地警报
紧急联系人：已配置 2 / 3
最近事件：无

[ 我感觉不适 ]
```

状态卡片持续提示：

- 未配置联系人
- 手机离线
- 权限缺失
- 手表未佩戴
- 待发送事件

## 10. 数据与隐私

最小化保存：

- 本地状态机状态
- 用户设置的心率阈值
- 佩戴与连接状态
- 求助事件、发送状态和解除状态
- 用户主动求助时获得的最近可用位置

联系人信息优先保存在手机侧。真实后端接入前必须补齐：

- 单独的敏感信息授权
- 联系人知情提示
- 传输加密
- 后端访问控制
- 数据保留期限
- 删除和撤回同意入口
- 面向目标市场的隐私政策

## 11. 测试与发布门槛

### 11.1 自动化测试

状态机必须支持纯函数或依赖注入式模拟输入，覆盖：

- 跑步持续活动进入守护
- 普通停留不误触发
- 高心率但仍移动只提示减速
- 突然停止和持续心率异常进入高危候选
- 无新心率读数不单独触发
- 未佩戴暂停判断
- `30 秒` Alarm 到时升级
- 用户确认取消
- 主动求助
- 手机离线排队与恢复连接补发
- 风险解除通知

### 11.2 模拟器验证

- 圆形与方形屏幕
- 首次引导
- 模拟演练
- 系统通知按钮
- 快捷卡片入口
- 能力降级分支
- 演示后端适配器

### 11.3 真机验证

安全类应用不得仅凭模拟器结果上架。上架前至少使用一款 `API_LEVEL 3.0+` 真机验证：

- 后台服务长时间存活
- 系统状态变化后服务恢复
- 心率、步数、距离和佩戴状态的回调频率
- `Alarm` 在息屏和后台场景下的准确性
- 通知、按钮、震动和声音
- 蓝牙断开与恢复后的补发
- GPS 临时定位的成功率和超时
- 电量消耗
- 真实跑步与健走样本中的误报率

面向更多设备上架前，需要建立设备兼容矩阵并增加真机覆盖。

### 11.4 校准门槛

自动联系人求助上线前，必须完成以下校准：

- 与运动医学顾问复核高危组合和面向用户的描述
- 使用真实跑步、健走、等红灯、休息、摘表和佩戴松动样本验证误报
- 明确高危候选的持续时间窗口
- 明确年龄建议值与用户可调整范围
- 在测试构建中收集匿名、最小化的诊断日志，取得单独同意

在校准完成前，测试构建可以执行本地提醒和演示求助，但不得向真实联系人自动发送消息。

## 12. 合规边界

上架名称、介绍和截图中避免使用：

- 防止猝死
- 心脏病预警
- 心脏骤停检测
- 跌倒检测
- 自动急救
- 保证通知到联系人

建议使用：

- 运动异常守护
- 运动异常提醒
- 运动安全辅助
- 紧急联系人求助辅助

真实短信和语音服务、海外销售或健康数据后端存储上线前，应由律师根据目标市场复核隐私、消费者保护、医疗器械边界和第三方联系人通知规则。

## 13. 后续增强

- 单独发布 `API_LEVEL 3.6+` 运动扩展包
- 接入真实短信和语音供应商
- 增加独立手机 App，提供更完整的定位和通知能力
- 在华米提供系统级权限的前提下评估后台摔倒检测
- 在独立通信设备上评估无手机远程求助
